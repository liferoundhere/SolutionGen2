Reference · Skill pack and design guidance

      
One look and one engine. Every story comes from the brief.

      
The cisco-3d-stage skill is a look and an engine, not a talk. It turns a story into a Three.js web app that moves like a deck, where every scene is its own lit 3D world. The generator's prompt points the build at it, so every preset comes out on brand and passes the same review.

Copy rules

        
    
          
  • No em dashes anywhere. Use commas, colons, or separate sentences.
    • 
          
  • Headline: a statement, then the outcome in the gradient clause.
    • 
          
  • Eyebrows carry a number and a chapter: 03 · The method.
    • 
          
  • Notes are written for the ear. Mark new clicks with "Click."
    • 
          
  • The narrator is always disclosed as AI and never impersonates the presenter.
    • 
        

      

      

        
Quality bar

        
    
          
  • Every world means something for its scene, and every click changes it.
    • 
          
  • Adjacent scenes never share a sky palette or a particle formation.
    • 
          
  • Text never sits on bright geometry; labels stay crisp after bloom.
    • 
          
  • Keys, clicks and deep links work; typing never navigates.
    • 
          
  • At 390px the HUD sits at the bottom with no overflow.
    • 
          
  • No console errors. Facts accurate or labelled modeled.
    • 
        

      

      

        
Security

        
    
          
  • No API keys, tokens or passwords in source, media or published files.
    • 
          
  • Live links accept https:// only; link edits stay in the browser.
    • 
          
  • Narration is pre-rendered, so the published site calls no API at runtime.
    •

Reference · Models and orchestration

      
Always a multi-agent build. Always the most capable model.

      
These prompts ask for research, design, a 3D build and a critical review inside one time budget. That work goes best when one agent orchestrates and sub-agents work in parallel, on Claude Opus 5.5 or the equivalent model from your provider.

    

    

      
ProviderOrchestrator (run the prompt here)Sub-agentsWhere to run it

      
        
Anthropic (recommended)Claude Opus 5.5 claude-opus-5-5, effort set to high or xhigh. Its default effort is medium, so raise it. For the hardest builds, Claude Fable 5.1 claude-fable-5-1.Claude Sonnet 5.5 for judgment-heavy work such as review; Claude Haiku 5.5 for reading-heavy research.Claude Code with sub-agents and workflows; the Claude Agent SDK; or Claude Managed Agents, whose outcomes feature has a separate grader iterate against your rubric.

        
OpenAIThe most capable GPT model available. At the time of writing, GPT-5.5.A smaller, faster model from the same family.Codex.

        
GoogleThe most capable Gemini model available. At the time of writing, the Gemini 3.5 family.Gemini Flash.Antigravity.

      
    

    

      

        
Making the time budget real

        
    
          
  • The prompt sets the budget as a ceiling, not a target: go deep, don't rush, finish early only when the work clears the bar, and check the clock while working.
    • 
          
  • A prompt can only ask. To enforce the limit, set it in the harness as well: a session budget in Claude Managed Agents (a hard spending cap), or a task budget on the Claude API (a token ceiling the model can see and pace itself against).
    • 
          
  • In Claude Code, watch the session and stop it at the deadline if it runs long.
    • 
        

      

      

        
Why multi-agent

        
    
          
  • Research, design, build and review run in parallel, so more of the budget goes into depth.
    • 
          
  • A separate reviewer judges the running build. Models tend to rate their own work too kindly, and an outside reviewer corrects for that.
    • 
          
  • The orchestrator keeps the brief and the bar in view while the sub-agents fill their own context with reading and code.
    • 
        

      

    

    
Model lineups change often. Confirm the current top model on each provider's documentation before a big build.

  


  

    

      
04 · Install

      
Download once. Build the next verse in an afternoon.

      
Install the skill into the agent you build with, run the starter to confirm it works, then paste a prompt from this page with "Build with the cisco-3d-stage skill pack" switched on.

    


    

      

        
Get the SEVerse-Skill pack

        
The cisco-3d-stage skill lives in the SEVerse-Skill repository: SKILL.md, six reference guides, and a runnable 7 scene starter with its tools, vendored three.js r170 and fonts. On GitHub, choose Code, then Download ZIP, which saves SEVerse-Skill-main.zip. If you do not have access, ask Stephen Ewings.

        
The pack's examples folder holds screenshots of internal customer talks. Keep it inside Cisco and leave it out of anything you share externally.

      

    


    
Not in this pack: the base cisco-branded skill (palette, type, glass panels and scroll explainers) is referenced by cisco-3d-stage but is not included in this zip. Everything this generator needs is covered by cisco-3d-stage on its own. If you have cisco-branded, install it beside it the same way and the agent reads both.


    

      
      
      
    


    

      
    
        
  1. Unzip the pack
    From the folder where you saved the download.
    
          
    unzip SEVerse-Skill-main.zip
    2. 
        
  2. Copy the skill into your skills folder
    Personal install, available in every project:
    
          
    mkdir -p ~/.claude/skills && cp -R SEVerse-Skill-main/cisco-3d-stage ~/.claude/skills/

    3. 
        
  3. Confirm Claude sees it
    Start a new Claude Code session in your build folder and ask which skills it has. It should list cisco-3d-stage. A cloud session needs the project install, committed to the repo.
    
          
    claude "Which skills do you have? Summarize cisco-3d-stage in two lines."
    4. 
      

    

    

      
    
        
  1. Make a zip with the skill at its root
    The app expects the skill folder itself inside the zip, not the whole repository.
    
          
    unzip SEVerse-Skill-main.zip && cd SEVerse-Skill-main && zip -r cisco-3d-stage.zip cisco-3d-stage
    2. 
        
  2. Upload it
    In claude.ai or the Claude desktop app, open Settings, then Capabilities, and upload cisco-3d-stage.zip under Skills. Code execution must be on. Menu names can differ by plan; your workspace admin may need to allow custom skills.
    3. 
        
  3. Know the limit
    The app can plan scenes, write copy, notes and narration, and draft the build. Running the starter, rendering voices, and the headless review need a terminal, so use Claude Code or Cursor for the full build.
    4. 
      

    

    

      
    
        
  1. Unzip and copy
    
          
    unzip SEVerse-Skill-main.zip && mkdir -p ~/.cursor/skills && cp -R SEVerse-Skill-main/cisco-3d-stage ~/.cursor/skills/
    2. 
        
  2. Reload Cursor
    Open a new agent chat. The agent picks the skill up from SKILL.md when you ask for a 3D or interactive presentation.
    3. 
      

    


    

      

        
Check the starter runs

        
A 7 scene sample that exercises every layout. It does not run from file://; serve it.

        
cd ~/.claude/skills/cisco-3d-stage/starter
python3 -m http.server 8765

        
Open http://localhost:8765/. Arrow keys step, P opens the presenter window, T the talking points, ?talktrack the printable talk track.

Narrated edition

node tools/export_narration.mjs tmp/narr.json
bash tools/sync_narrated.sh ../narrated
python3 tools/gen_audio.py tmp/narr.json ../narrated/audio

Review, docs, publish

        
npm i -D puppeteer-core
node tools/review.mjs http://localhost:8765/ 1440 900
node tools/review.mjs http://localhost:8765/ 390 844
node tools/gen_docs.mjs ../narrated/audio/manifest.json

        
Publish to any static host with HTTP range support (here.now works). Keep hosting keys in the CLI's credential file, never in the repo, and leave tmp/ and node_modules/ out.

    06 · After the first build
    
        
    Edit one thing at a time
    
      
    
      
      
        
    • Refine in plain language: a bigger title, slower transitions, a reordered scene, a corrected label.
      • 
        
    • Never regenerate the whole experience to fix one detail. Edit the scene, panel or label and keep the rest.
      • 
        
    • After every edit, recheck the provenance labels and the Assumptions panel.
      • 
        
    • A modeled figure that moves into the headline carries its label with it.
      • 
        
    • Re-run tools/review.mjs at 1440 and 390 after any layout change.
      • 
      
    
      
    If you use guided mode
    
      
      
        
    • When it shows you a storyboard, check that each panel says what is on screen and carries one idea.
      • 
        
    • Something on screen should change every few seconds; every click changes the world.
      • 
        
    • Any estimate should be marked on the panel itself, not only in a footer.
      • 
        
    • Answer its questions briefly, then let it build.
